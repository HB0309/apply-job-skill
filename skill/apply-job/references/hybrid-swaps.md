# HYBRID swaps — read ONLY when the `TRACK` line of `jobkit skills` says `HYBRID: <a>+<b>`

One base alone would hide half of what a hybrid posting wants, so these swaps are **REQUIRED**
(not "only when it clearly beats"). Pull each entry with
`python bin/jobkit.py pool entry "<name>"`, then page-fit as usual. **A swap replaces; it never
adds a fourth project.** State the base, the HYBRID tag and every swap in the match report's
Selection section.

The swap table is yours to write: for each pair of tracks, name which pool entry replaces
which, which alternate framing the kept entries switch to, and which skills row moves up.
The one rule is that a swap replaces an entry; it never adds one. Example shape:

- **security base + ai**: replace <Project E> with <Project A>, using its safety framing; <Employer B>
  uses its ML/AI framing alternates; add the `Machine Learning & AI` skills row above the
  framework rows.
- **ai base + security**: the <Employer A> entry carries its security bullet; keep one
  security tools row in the skills table.
- **software base + ai** or **ai base + software**: no entry swap when both bases already
  carry the same projects; reorder projects and pick the AI-forward alternate bullets.
